# Kostlim Design — v2: Приват Пак, тренажёр, планер (обновление после багфикса)

## Что изменилось по сравнению с прошлым архивом

Нашёл и исправил 3 реальные причины проблем (проверил всё вживую на настоящем
PostgreSQL у себя, не только визуально):

1. **ИИ не отвечал в чате тренажёра** — лимит `maxOutputTokens: 400` для
   `gemini-2.5-flash` съедался внутренним "thinking" модели ещё до генерации
   текста ответа. Убрал `thinkingConfig.thinkingBudget = 0` и поднял лимит.
2. **Кнопки были чёрные/невидимые** (и в тренажёре, и изначально в
   `resources.php`, ваш баг №1 из самого первого сообщения) — везде
   использовался класс `.save-all-btn`, который в вашем `style.css` реально
   стилизован ТОЛЬКО внутри `price.php`, больше нигде. Переписал `ai_trainer.php`
   и `planner.php` на собственные самодостаточные стили (без чужих классов).
3. **Не было единого раздела «Приват Пак»** — добавил `privat_pak.php`,
   визуально скопировав 1-в-1 реальные классы вашей страницы `support.php`
   (`support-wrap`, `support-admin-card`, `support-action-btn` и т.д. — взял
   их прямо из вашего кода).

Также вынес всю проверку доступа (admin/PPK) в один файл
`includes/ppk_access.php` вместо копий по каждому файлу — меньше риска, что
в следующий раз где-то разъедется логика.

## ⚠️ Как переносить файлы (чтобы не повторить прошлый инцидент)

В прошлый раз при переносе исчезли `index.php`, `bot.php`, `resources.php` —
скорее всего, папка архива перетащили поверх корня репозитория, и что-то
удалилось при синхронизации. В этот раз, пожалуйста:

- **Не перетаскивайте папку целиком.** Копируйте файлы по одному, в том же
  пути, что указан ниже, в уже существующую структуру репозитория.
- Либо, если удобнее — через веб-интерфейс GitHub: "Add file" → "Upload files"
  и перетащить туда ТОЛЬКО файлы из этого архива (по одному или всей пачкой,
  но не как замену папки).
- После переноса проверьте `git status` (или превью загрузки на GitHub) —
  там должны быть только НОВЫЕ/ИЗМЕНЁННЫЕ файлы из списка ниже, ноль удалений
  существующих файлов. Если видите в diff'е "deleted" на файл, которого нет
  в этом списке — остановитесь и не пушьте.

## Шаг 1. Скопировать файлы

Так же, как в прошлый раз — пути внутри архива совпадают со структурой
репозитория. `assets/kostlim-upgrade.css` из прошлого архива **больше не
нужен и не используется** — можно удалить, если он остался, вреда не будет,
но и обязательности в этом нет.

## Шаг 2. SQL-миграция

Если вы уже прогоняли `database/2026_09_kostlim_upgrade.sql` в прошлый раз —
повторно запускать не обязательно (она идемпотентна, но и не изменилась).
Если ещё не прогоняли:
```bash
psql "$DATABASE_URL" -f database/2026_09_kostlim_upgrade.sql
```

## Шаг 3. Проверить переменную окружения GEMINI_API_KEY

Раз ваш ИИ-ассистент в поддержке (`ai_support.php`) уже работает на проде —
значит, `GEMINI_API_KEY` уже настроен, и тренажёр будет использовать тот же
ключ автоматически. Ничего дополнительно делать не нужно.

## Шаг 4. Добавить ссылку на «Приват Пак» в навигацию

Это единственная правка в существующих файлах, которая реально нужна для
доступа к новому разделу. Проще всего — добавить пункт в `quick-actions-grid`
на главной (`index.php`), рядом с остальными плитками (На главную/Прайс/Отзывы
и т.д.). Найдите там блок `<div class="quick-actions-grid">` и добавьте внутрь
ОДНУ строку (ничего не удаляя):
```html
<a href="privat_pak.php" class="quick-action-btn">
    <svg width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2.5"><path d="M12 2a5 5 0 0 0-5 5v3H6a2 2 0 0 0-2 2v8a2 2 0 0 0 2 2h12a2 2 0 0 0 2-2v-8a2 2 0 0 0-2-2h-1V7a5 5 0 0 0-5-5zm-3 8V7a3 3 0 0 1 6 0v3z"/></svg>
    Приват Пак
</a>
```
Сделайте то же самое в `support.php` и где ещё есть `quick-actions-grid` —
на ваше усмотрение, это не обязательно везде сразу, можно начать с главной.

Раздел сам разберётся, показывать ли содержимое или экран "нужен доступ" —
никакой отдельной проверки в самой ссылке не нужно.

## Шаг 5. Множественные плашки ADMIN + PPK на главной и в профиле

Это по-прежнему нужно внести вручную (2 маленькие правки, я специально не
трогаю ваши большие файлы автоматически). В `index.php`, в блоке плашки
профиля, сейчас примерно так:
```php
<?php if ($isAdmin): ?>
    <span class="tg-admin-tag">admin</span>
<?php elseif ($isPackDesigner): ?>
    <span class="tg-admin-tag" title="Designer PPK">PPK</span>
<?php endif; ?>
```
Замените `elseif` на два независимых `if` (только это, больше ничего трогать
не нужно):
```php
<?php if ($isAdmin): ?><span class="tg-admin-tag">ADMIN</span><?php endif; ?>
<?php if ($isPackDesigner): ?><span class="tg-admin-tag" title="Designer PPK">PPK</span><?php endif; ?>
```
Это и есть та самая правка из ТЗ — раньше `elseif` физически не давал
показать сразу обе плашки никому, даже главному админу.

В `profile.php` для той же плашки — там сейчас `$isPackDesigner` вообще не
вычисляется. Добавьте рядом с вычислением `$isAdmin`:
```php
require_once __DIR__ . '/includes/ppk_access.php';
$access = resolvePpkAccess($pdo);
$isPackDesigner = $access['isPackDesigner'];
```
и в разметке рядом с плашкой ADMIN добавьте:
```php
<?php if ($isPackDesigner): ?><span class="tg-admin-tag" title="Designer PPK">PPK</span><?php endif; ?>
```
(используя тот же класс `tg-admin-tag`, что уже есть у вас для ADMIN — просто
скопируйте его вид, чтобы плашки смотрелись одинаково).

## Проверка после деплоя

1. `privat_pak.php` под главным админом — видно ОБЕ плашки (⚡Admin и 🎨PPK)
   в карточке профиля хаба, и все 4 строки-перехода (ресурсы/тренажёр/
   планер/админ-инструменты).
2. Открыть `privat_pak.php` без доступа (в приватном окне браузера, не
   авторизуясь) — должен показаться экран "Доступно владельцам пака" с
   кнопкой покупки и полем ключа, а не голый 403.
3. `ai_trainer.php`: "+ Новый заказ" — оранжевая, видимая кнопка → анкета →
   после отправки ИИ должен прислать текстовое ТЗ (не "…" и не предупреждение
   про ключ, если GEMINI_API_KEY настроен) → пара сообщений в чате → ответы
   приходят текстом → «Сдать работу» с картинкой → оценка и отзыв.
4. `planner.php`: "+ Добавить клиента" → заполнить строку → обновить
   страницу → данные должны остаться (автосохранение по паузе в 500мс после
   ввода).
5. На главной и в профиле — обе плашки видны у главного админа, у обычного
   участника пака — только PPK.

## Если что-то снова не так

В этот раз я прогнал `start_session`, `send_message`, `get_session`,
`submit_work` (с реальной загрузкой файла), `share_with_admin`,
`save_row`/`list_rows` планера — и все страницы доступа (с доступом, без
доступа, 403) — вживую на настоящем PostgreSQL у себя, без единой PHP-ошибки.
Если после этого что-то не заработает на вашем сервере — это будет либо
специфика окружения Render (переменные окружения, версия PHP-расширений),
либо ошибка при переносе файлов — в обоих случаях присылайте точный текст
ошибки/скриншот, и я проверю целенаправленно.
